# UI Audit — 2026-07-28

> Full-matrix visual/interaction audit of rmhstudios.com. **Audience: humans and
> coding agents.** Every finding is written so a future agent can locate, verify,
> and fix it without re-running the audit: each names the route(s), viewport(s),
> the evidence capture it was observed in, the suspected source file(s), the
> design principle violated, and a concrete fix direction.
>
> Companion docs: [`design-language.md`](./design-language.md) (the system this
> audit measures against), [`page-consistency.md`](./page-consistency.md) (the
> per-page checklist many findings map to).

## 1. Scope and method

**What was audited.** 40+ routes — signed-out core (`/`, `/login`, `/pricing`),
public content (`/news`, `/blog`, `/library`, `/help`, `/roadmap`, `/terms`,
`/rmh-capital`), the signed-in `_site` surface (feed, explore, arcade, settings,
messages, rmhladder, leaderboard, shop, market, predictions, notifications,
search, communities, events, study, homes, bookmarks, tournaments, store,
developer, game detail, profile), full-screen apps (`/rmhtype`, `/rmhtube`,
`/rmhmusic`, `/rmhstudy`, `/rmhcode`, `/rmhcalculator`, `/rmhbox`, `/daily`,
`/lights-out`, `/versecraft`), theme variants (Daylight default, Midnight
`graphite`, `high-contrast`), reduced motion, first-run overlays, and scripted
interactions (hub bloom, composer focus, wheel scroll, keyboard tab stops,
login validation, card hover).

**Viewport matrix.** 13 viewports; Tier-A routes got all 13, Tier-B routes got
the three key ones (marked •):

| name | size | class |
| --- | --- | --- |
| m320 | 320×568 | phone (smallest supported) |
| m375 | 375×667 | phone |
| m390 • | 390×844 | phone (iPhone 14 class) |
| m412 | 412×915 | phone (Pixel class) |
| mland844 | 844×390 | phone **landscape** |
| t768 • | 768×1024 | tablet portrait (touch) |
| t1024 | 1024×768 | tablet landscape (touch) |
| l1280 | 1280×800 | small laptop |
| l1366 | 1366×768 | common laptop |
| d1536 | 1536×864 | desktop |
| d1920 • | 1920×1080 | desktop |
| d2560 | 2560×1440 | large desktop |
| uw3440 | 3440×1440 | ultrawide 21:9 |

Mobile/tablet contexts ran with real touch emulation (`isMobile`, `hasTouch`),
so coarse-pointer styling paths were active. DPR 1 throughout.

**Instrumentation.** Playwright (project's own 1.61) drove the pre-installed
Chromium. Per page×viewport it captured a viewport PNG + full-page JPEG and ran
in-page checks: horizontal overflow (+ offending elements), interactive targets
under 44×44px, visible text under 12px, approximate WCAG contrast on **solid**
backgrounds (translucent glass surfaces were skipped to avoid false positives —
so the contrast lists are floors, not totals), unnamed buttons/links, images
without alt, h1 census, landmark presence, `document.getAnimations()` census
(and again under emulated reduced motion), console/page errors, failed
requests, and on the feed: CLS, LCP, long tasks, and rAF frame timing during a
scripted scroll. A signed-in test account (`@audituser`) with five seeded posts
exercised feed rendering; the ladder seed script populated companies/sources.

**Environment caveats — read before "fixing" a finding:**

- Dev server (Vite, unminified, cold per-route compile). All *latency* numbers
  are indicative only. Layout shift (CLS), missing skeletons, overlap, contrast,
  and target sizes are code-caused and valid.
- The outbound proxy blocked third-party CDNs (twemoji via jsdelivr). Findings
  only cite this where the UI's *failure handling* is the defect.
- Local DB was near-empty by design. Findings target empty-state *handling*,
  never emptiness itself.
- One harness incident is itself a finding: late in the signed-in run the six
  uw3440 Tier-A captures (and one m390 capture) silently rendered signed-out
  for a valid session (see AUD-060); they were re-captured signed-in and the
  re-captures are what the findings reference.

**Severity scale.**

- **P0** — broken/unusable: functionality or content effectively lost.
- **P1** — significant defect a normal user hits in normal use.
- **P2** — quality defect; noticeable, degrades trust/usability.
- **P3** — polish/consistency nit.

Principles referenced: Apple HIG (clarity, deference, depth; ≥44pt targets;
~11pt legibility floor; safe areas), Nielsen's 10 heuristics, WCAG 2.x (1.4.3
contrast, 2.5.8 target size, 1.3.1 structure, 2.4 navigation), and the repo's
own `docs/design-language.md` + `docs/page-consistency.md` canon (tokens,
PageLayout, LiquidTabs, EmptyState, spacing rhythm §15.4, floating-stack §5.5x).

**Finding IDs** are stable: `AUD-0xx` systemic, `AUD-1xx` signed-out core,
`AUD-2xx` public content pages, `AUD-3xx` signed-in site pages, `AUD-4xx`
full-screen apps, `AUD-5xx` themes/motion/interactions. Fix one, check its
"Also fixes / related" line — several route-level symptoms share a systemic
root.

## 2. Systemic findings (fix once, heal everywhere)

### AUD-001 [P1] `--site-text-dim` (#8a8a8a) is used for meaningful text and fails AA everywhere it appears
- **Category:** Readability (contrast). **Principle:** WCAG 1.4.3 (4.5:1 for normal text).
- **Where (measured 3.45:1 on the default light theme):** `/login` "RMH STUDIOS" 10.9px, "OR WITH EMAIL" 10.9px, **interactive** "Don't have an account? Sign up" 14px and "Back to home" 14px; `/pricing` eyebrow 11.5px, "/mo" & "/forever" 12px, "Your current plan" 14px, "Compare tiers" 10px; `/roadmap` all 15 era taglines 11px (worst page — AUD-205); `/news` empty-state copy 18px; nav-rail group title "RMH VENTURES" 10.2px on every ≥1280 page; What's New modal captions 10.4–11.2px; `/help` AI-accuracy disclaimer 11px.
- **Evidence:** automated contrast flags at every viewport in the out/in reports; visually verifiable in `out__login__d1920.png`, `out__roadmap__m390.png`, `out__pricing__l1366.png` (capture set, session artifacts).
- **Source:** token `--site-text-dim: #8a8a8a` in `app/globals.css` (≈line 113); call sites: `app/routes/login.tsx` ≈399/459/486–505, `components/membership/MembershipPanel.tsx` ≈281/310, `components/roadmap/RoadmapSection.tsx` ≈884/943, `components/feed/PinnedHero.tsx` ≈112–115, `components/radial/radial.css` `.rad-rail__group-title` ≈565, `components/news/NewsList.tsx` ≈228, `components/assistant/ConciergePanel.tsx` ≈237, `components/feed/feed.css` ≈671/745.
- **Fix:** darken the token to ≥ #767676 (4.5:1 on white) **or** migrate all text that carries meaning (links, labels, disclaimers, prices) to `text-site-text-muted`, reserving `-dim` for decorative ≥18px text. Audit each call site above after the token change — several pair the color with sub-12px sizes (AUD-002).

### AUD-002 [P2] House "micro-caps" style stacks three legibility penalties: ≤11px + ALL-CAPS wide tracking + dim color
- **Category:** Readability. **Principle:** HIG ~11pt floor; WCAG 1.4.3.
- **Where:** section eyebrows, kickers, badges and rail captions across the site: 10px "Most popular"/"Current"/"Compare tiers" (`/pricing`), 10.9px feed-card kickers, 10.2px "RMH VENTURES", 10.9px "RMH STUDIOS"/"OR WITH EMAIL" (`/login`), 11.5px skip link (`.radial-skip`), 9.3px library stat captions (single worst: AUD-213).
- **Fix:** establish an 11px (0.6875rem) hard floor for micro-caps (12px preferred), pair with `--site-text-muted`, and sweep: `text-[10px]`, `text-[0.68rem]`, `text-[0.65rem]`, `font-size: 0.5xrem` occurrences under `components/` and `app/`.

### AUD-003 [P1] Fixed bottom-center hub orb occludes content and collides with other floating chrome
- **Category:** Layout integrity / fixed chrome. **Principle:** HIG deference & safe areas; Nielsen visibility.
- **Symptoms (each also listed at its route):**
  - Orb sits **on top of the cookie-consent banner text** at every ≥768px viewport on every `_site` route — the §5.5x floating-stack coordination that solves exactly this is wrapped in `@media (max-width: 767.98px)` and never runs on md+ (`app/globals.css` ≈2012–2060). Consent copy and its "Learn more" link are hidden behind the orb (AUD-102).
  - Orb covers feed-card text/counters on portrait phones — the feed column and orb share the same center axis and no bottom clearance is reserved (AUD-104).
  - Orb overlaps `/pricing` tier-card feature lists mid-scroll and hides the pinned hero's "Compare tiers" scroll cue entirely (cue `bottom-8` sits inside the orb's 28–100px reserved band; `components/feed/PinnedHero.tsx` ≈109–122) (AUD-111).
  - Orb sits permanently on `/help`'s bottom-pinned concierge suggestion chips (`h-screen` layout, no `pb-dock`) (AUD-203).
  - At 844×390 landscape, orb + cookie bar + topbar leave ~150px of usable content height (AUD-105).
- **Source:** `.radial-hub__orb` fixed at `left: 50%`, z-index `var(--z-floating)`=80 in `components/radial/radial.css` ≈707–720.
- **Fix (one coordinated change):** (a) extend the floating-stack `:has()` coordination to all widths so banner/FAB/orb never share pixels; (b) publish the orb's occupied band as a CSS var (inset + size already exist: `--site-hub-orb-inset`, `--site-hub-orb-size`) and consume it as bottom clearance in feed wheel, `h-screen` pages, and pinned-hero cues; (c) consider a subtle glass scrim behind the orb so text passing beneath stays legible.

### AUD-004 [P2] Interactive targets under the 44px floor across the shared chrome and primitives
- **Category:** Interactivity / HIG ≥44pt / WCAG 2.5.8.
- **Recurring offenders (flagged on nearly every page at every touch viewport):** topbar Search 40×40, topbar brand 47×25, topbar "Sign in" 75×36; cookie-consent "Essential only"/"Accept all" 36px (`Button size="sm"` = h-9; these are legally meaningful); live-rail trending rows 33px; deck tabs 36px; language-modal rows and "Continue in English" 36px; `Button size="sm"` generally. Route-specific pileups: `/shop` 19–22 flags, `/homes` 17–25, `/search` 25 @d1920, `/rmh-capital` 15–18, `/messages` 11–15, `/blog` & `/library` 12–15 (LiquidTabs at 36–38px), `/help` chips 30px, `/login` text links 20px tall.
- **Fix:** on coarse pointers, extend the *hit area* (padding or `::after` overlay) to ≥44×44 without changing visuals: `.radial-topbar__btn`, `.radial-topbar__signin`, `.radial-topbar__brand` (`components/radial/radial.css` ≈235–260), `rad-live__row`, cookie-consent buttons (`components/site/CookieConsent.tsx` ≈90–95 — use default `h-11` size), LiquidTabs min-height (`components/ui/liquid-tabs.tsx` ≈234 + `[data-slot='liquid-tabs']` rules in `app/globals.css` ≈4462). The design language already promises "44px targets restored for coarse pointers" (§15.4) — this closes the gap between promise and build.

### AUD-005 [P2] Heading-outline discipline is broken site-wide (missing h1s and duplicate h1s)
- **Category:** A11y/SEO structure. **Principle:** WCAG 1.3.1/2.4.6.
- **Zero h1:** `/` (both signed states, all 13 viewports — outline starts at a 10px `h2` rail caption), `/arcade`, `/leaderboard`, `/search`, `/rmhcalculator`, `/rmhtube` (some vps), `/rmhtype` (some vps), `/u/<handle>`.
- **Two+ h1s:** `/pricing` (AppleHero + PinnedHero, and the second reads "Choose youraltitude." with no space across its `<br/>` — `components/feed/PinnedHero.tsx` ≈89–94), `/shop`, `/store` (three at d1920), `/market`, `/communities`, `/events` (extra h1 appears only ≥t768), `/games/$gameId`.
- **Fix:** add an `sr-only` h1 to headerless routes; make PinnedHero's tag a prop and demote to h2 wherever a route already supplies an h1; find the width-gated duplicate heading on communities/events/market and demote it.

### AUD-006 [P2] Reveal-on-scroll gating renders whole pages invisible without a fired IntersectionObserver
- **Category:** Robustness / progressive rendering. **Principle:** Nielsen visibility; content must not require JS scroll events.
- **Where:** `/pricing` — entire 4-card plan grid + footnote at opacity 0 (framer `whileInView`, `components/membership/MembershipPanel.tsx` ≈241/362 + `components/motion/RevealGroup.tsx`); `/rmh-capital` — all body sections (`.reveal{opacity:0}` in `components/rmh-capital/rmh-capital.css` ≈300 + `useReveal` in `components/rmh-capital/shared.tsx` ≈26–51), leaving hero+ticker+footer around a ~4,700px void.
- **Impact:** blank in print, full-page capture, reader mode, pre-hydration, and any environment where the observer doesn't fire; it also hid the pricing cards from this audit's primary pass (re-captured with scripted scrolling: `supp__pricing-scroll-*`).
- **Fix:** make revealed the default; add the hiding class only once JS has armed the observer (or use CSS `animation-timeline: view()` with a completing fallback), plus a `noscript`/timeout force-visible path.

### AUD-007 [P2] React hydration mismatch fires on every `_site` page load
- **Category:** SSR integrity. **Principle:** Nielsen consistency/error prevention.
- **Evidence:** console census logged "A tree hydrated but some attributes of the server rendered HTML didn't match the client properties…" on effectively every route/viewport, both signed states.
- **Suspects (in likelihood order):** the signed-out composer placeholder that ignores session state (AUD-107); `timeAgo(createdAt)` relative strings rendered during SSR (`components/radial/RmharkCard.tsx` ≈57); attribute divergence with the anti-FOUC inline theme/locale scripts in `app/routes/__root.tsx`.
- **Fix:** reproduce with React 19 hydration diffing enabled, fix the divergent attribute(s); gate session-dependent and time-relative renders behind mount or pass server "now"/session snapshot as props.

### AUD-008 [P1] `lib/icons.ts` deep-imports crash SSR intermittently (profile route captured falling back to client-only render)
- **Category:** Robustness. **Principle:** engineering hygiene surfaced by UI audit (user-visible as slow/blank first paint).
- **Evidence:** `/u/audituser` @d1920 pageError: `Switched to client rendering because the server rendering errored: Cannot find module 'lucide-react/dist/esm/icons/pause' imported from lib/icons.ts`; @m390 logged the paired "recovered by client render" error.
- **Root cause (verified):** `lib/icons.ts` re-exports ~every icon via extensionless deep paths (`lucide-react/dist/esm/icons/pause`); installed lucide-react ships **no `exports` map**, so resolution rides each bundler's resolver and intermittently fails under the Vite SSR module runner. The file's own header says it exists "to avoid **Turbopack** module resolution bugs" — a stale Next.js-era workaround; this repo is Vite (see CLAUDE.md trust order).
- **Fix:** replace with plain `export { Pause, Play, … } from 'lucide-react'` (Vite tree-shakes lucide fine), or at minimum append `.mjs` to every deep path. Then delete the Turbopack comment.

### AUD-009 [P2] Empty states are inconsistent — the canonical `EmptyState` primitive is bypassed with bare strings and misleading copy
- **Category:** Empty/edge states; consistency. **Principle:** Nielsen recognition/recovery; repo canon (`components/ui/empty-state.tsx`).
- **Instances:** `/news` blames "your filters" and offers "Clear All Filters" to users who set none (`components/news/NewsList.tsx` ≈228–234); `/library` mixes the canonical EmptyState (music) with a bare "No books match that search." one-liner when search is untouched (`app/routes/_site/library/index.tsx` ≈681); home side-deck renders bare "Nothing here yet." / raw "Loading..." strings (`components/radial/RadialSideFeed.tsx`); feed loading shows an unlabeled goo blob with no skeletons (AUD-108).
- **Fix:** route all of these through `EmptyState` (icon/title/description/action) with state-aware copy (query set vs. not), and skeleton rows for loading.

### AUD-010 [P3] First-run overlay pileup: language modal → What's New marketing modal → cookie consent
- **Category:** Minimalism; user control. **Principle:** Nielsen aesthetic/minimalist; consent-first ordering.
- A brand-new visitor must dismiss three stacked interruptions before reading any content; the legally required consent bar is painted *behind* the promotional overlays (`components/site/LanguageFirstRunModal.tsx`, `components/feed/WhatsNewModal.tsx`, `components/site/CookieConsent.tsx` mount independently with no sequencing). On m390 the What's New modal covers ~95% of the viewport.
- **Fix:** sequence first-run surfaces (consent first or alone on visit 1; What's New deferred to visit 2 / post-interaction); fold language choice into a passive topbar hint.

### AUD-011 [P3] Session can silently render signed-out for an authenticated user under load
- **Category:** Robustness / trust. **Confidence: medium (mechanism unconfirmed).**
- During the signed-in run, 6 of 7 uw3440 captures and 1 m390 capture rendered the signed-out shell (Sign-in pill, "Sign in to post RMHarks") for a session that was still valid — immediate re-capture with the same cookies rendered signed-in. Most plausible mechanism: `getSession`/loader failure under the harness's request burst (in-memory rate limiter?) being treated as "no session" instead of an error state.
- **Fix direction:** distinguish "session lookup failed" from "no session" in the SSR path; on failure, render a neutral/retry state rather than the signed-out UI (which invites duplicate logins and confuses users).

## 3. Signed-out core (`/`, `/login`, `/pricing`) — AUD-1xx

### AUD-101 [P0] `/pricing` Starter "Subscribe" label is invisible (≈1.15:1); Pro's gold CTA and "Most popular" ribbon ≈2.43:1
- **Category:** Readability/CTA. **Principle:** WCAG 1.4.3; token discipline (page-consistency §"ink tracks its surface").
- **What's wrong (verified in `supp__pricing-scroll-s04__d1920.png` — Starter's black pill shows a barely-detectable ghost label):** `components/membership/MembershipPanel.tsx` ≈320–328 hardcodes dark ink for both featured and Starter buttons — `color: plan.featured || plan.tier === 'starter' ? '#1a1505' : 'var(--site-accent-fg)'`. Default theme `--site-accent` is `#000000`, so Starter renders near-black-on-black on the page's main purchase CTA. Pro's button + the 10px `pricing-ribbon` put the same dark ink on `--site-warning: #7a4a00` (a dark brown, not the bright gold the ink assumes).
- **Fix:** remove `|| plan.tier === 'starter'`; introduce a paired `--site-warning-fg` token (per the "ink tracks its surface" rule) instead of hardcoded `#1a1505`; consider brightening `--site-warning` in the default theme. Re-check in Midnight/high-contrast.

### AUD-102 [P1] Cookie banner vs orb vs Compose FAB collisions at md+ (all `_site` routes)
- See systemic AUD-003. Signed-out specifics: at 768–844px the banner's "Accept all" stacks directly on the "Compose" FAB — two black pills overlap and a tap aimed at one can hit the other (`out__home__mland844.png`, `out__home__t768.png`: Compose reduced to a clipped "…ose" sliver). **Fix at the systemic root.**

### AUD-103 [P1] Signed-out home briefly shows a functional-looking composer, then swaps to the sign-in card
- **Category:** Consistency; honest affordances. **Principle:** Nielsen match of system & display.
- Before the lazy composer chunk mounts, signed-out visitors see "What's on your mind?" with a fabricated "U" avatar; it then visibly morphs into "Sign in to post RMHarks". `components/feed/ComposeBoxLazy.tsx` `ComposePlaceholder` (≈66–115) never checks the session, while the real `components/feed/ComposeBox.tsx` ≈410 does. Also the prime hydration-mismatch suspect (AUD-007).
- **Fix:** render the sign-in prompt directly in the placeholder when there is no session.

### AUD-104 [P1] Hub orb occludes feed content on portrait phones — see AUD-003(b). Evidence: `out__home__m320/375/412.png` (orb covering counts/author rows); end-of-feed leaves <40px clearance after the last card.

### AUD-105 [P1] Landscape phone (844×390): floating chrome consumes ~60% of the viewport height on first visit (topbar + cookie bar + orb + FAB). See AUD-003(e). Design decision needed: collapse the orb to a corner or shrink chrome under `max-height: ~480px` media conditions.

### AUD-106 [P2] Raw enum `GAME_ANNOUNCEMENT` printed as the kicker on announcement feed cards
- 10.9px uppercase database identifier on ~half the signed-out home cards (`components/radial/RmharkCard.tsx` ≈65 renders `{item.category || item.type}` untranslated; `radial.css` ≈1524 uppercases at 0.68rem). Violates the repo's own i18n rule (CLAUDE.md #5).
- **Fix:** translate via `t('kicker.' + type, { defaultValue: humanize(type) })`; raise size to ≥11px.

### AUD-107 [P2] Long posts hard-clamp at 5 lines mid-word with no "Show more" and no detail affordance on phones (`radial.css` ≈1514–1522 `-webkit-line-clamp: 5`; no expander in `RmharkCard.tsx`). Desktop shows the full text; phones get an arbitrary prefix. **Fix:** clamp-detect and add a Show-more toggle or link the card to the thread route.

### AUD-108 [P2] Feed loading state: an unlabeled metaball blob in an otherwise blank column; side deck says raw "Loading..."
- No card skeletons exist anywhere in the wheel; frozen mid-morph the goo loader reads as an ink-blot glitch, and at wide viewports it rides the column axis (~220px left of the composition's ring center at 1920). Dev-server latency inflated the *duration* only; the *affordance* is the defect (site canon requires `<Skeleton>` blocks — page-consistency §States).
- **Fix:** 3–4 glass card skeletons matching `RmharkCard` geometry; skeleton rows in the deck; center the loader on one axis deliberately.

### AUD-109 [P2] Emoji become blank mid-sentence runs when the twemoji CDN is unreachable
- Twemoji swaps native glyphs for `<img>`s from jsdelivr with **no onerror fallback**, so blocked/failed loads silently delete post content (evidence: the seeded emoji post shows a ~180px empty run then an orphaned em-dash at every viewport). Environment triggered it here; ad-blockers/CSP/firewalls trigger it in the wild.
- **Fix:** `onerror` → restore `alt` text (the original emoji) in `components/ui/TwemojiProvider.tsx`; consider self-hosting the SVG set under `public/` (also aligns with the site's CSP posture).

### AUD-110 [P2] `/pricing` page structure: two stacked full heroes push prices 3+ screens down; duplicate h1s
- Route-level `AppleHero` sits directly above `MembershipPanel`'s own pinned hero (2.6 viewport-heights of pinned scroll on md+): ~2,800px of scroll on 1080p before any price. Both render h1s (see AUD-005), the second concatenating to "Choose youraltitude.". `app/routes/_site/pricing.tsx` ≈53–61.
- **Fix:** one hero (drop the route-level AppleHero or set the panel hero to `screens={1}` + demote its heading).

### AUD-111 [P2] `/pricing` polish cluster (all verified):
- Aura blur clipped into hard-edged rectangles behind the hero (`.apple-hero` `overflow: clip` + auras positioned outside the box with `blur(46px)`, `app/globals.css` ≈4295–4371) — reads as a rendering bug at ≥1024w. Fix: mask-fade before the clip line.
- "Compare tiers" scroll cue rendered *inside the orb's footprint* → never visible (AUD-003).
- Signed-out visitors see Free marked "**Current**" with a disabled "Your current plan" slot (`pricing.tsx` ≈23 maps anonymous → `'free'`). Fix: "Get started — free" → `/login`.
- Plan grid has no intermediate column count (`lg:grid-cols-4`, else 1 col): four stacked full-width cards at 768–1023, squeezed ~230px columns at 1024. Fix: `sm:grid-cols-2 xl:grid-cols-4`. (Verified via `supp__pricing-scroll-*` captures.)
- Feed widgets (Trending / Who to follow) fill the pricing right rail at ≥1440 — social discovery content competing with a conversion pitch (`pricing.tsx` ≈64 `ContextRail reserve` → default live rail).

### AUD-112 [P2] `/login` affordance + structure cluster:
- "Don't have an account? Sign up" — the whole sentence is one 20px-tall dim-gray button; nothing marks the actionable phrase (no underline/weight/color). "Back to home" likewise 20px. `app/routes/login.tsx` ≈482–505. Fix: ≥44px hit areas; style the actionable span as a link.
- No `<main>` landmark, no skip link, and no cookie banner on `/login` (renders outside the `_site` shell; `CookieConsent` mounts only in `app/routes/_site.tsx` ≈37) — a deep-linked first visit gets no consent prompt while every shell page shows one.
- OAuth provider buttons are icon-only circles (Discord/Google/GitHub) — confirm `aria-label`s exist; visually fine.
- Glass card nearly indistinguishable from the near-white page at ≥1280 (no aurora behind top-level routes) — the material's depth premise collapses. Fix: render the ring/aurora backdrop behind the card or raise pane tint on light themes.

### AUD-113 [P1] What's New modal (first-run) defects — `components/feed/WhatsNewModal.tsx`:
- Dialog primitive's absolute close X collides with the modal's own "26 / 01" date in the same corner; the X is a hairline glyph over dark text — effectively invisible (m390 + d1920, `firstvisit__home__*.png`). Fix: pad `.spatial-whats-new__meta` right by the close button's footprint (~3rem) or move the date; give the X visible weight on the dark panel.
- Mobile footer: caption "Designed around the community." crushes into a 3-line sliver while the `w-full` CTA draws over it and bleeds past the card's rounded corner (`feed.css` ≈664–668 `space-between` row + `Button className="w-full sm:…"`). Fix: stack the footer column-wise under `sm`.
- Desktop: the three change-columns sit ~20px apart — tighter than the modal's own 32px outer padding (gutter hierarchy inverted). Fix: `gap-8`.

### AUD-114 [P2] Language first-run modal says "available in **32** languages" — the app ships **16** locales (`LOCALES` in `lib/i18n/config.ts`). `components/site/LanguageFirstRunModal.tsx` ≈62. Also: 12 options visible with no scroll affordance for the rest. Fix: interpolate `LOCALES.length`; add a fade/scroll cue.

### AUD-115 [P3] Signed-out feed extras: card stat rows (heart/comment/repost + counts) look like the universal action toolbar but are inert `<span>`s inside `aria-hidden` (`RmharkCard.tsx` ≈71–80) — taps do nothing and AT hears nothing. Fix: real buttons deep-linking to sign-in, or restyle as passive text metadata.
