# Harmonic — work packages

Each WP is sized for one session. "Done when" is the acceptance test: a reviewer checks
exactly these. Every WP also must: pass `pnpm check:consistency`, add or extend tests in
`pnpm test:tf2 lib/harmonic-game`, keep all user-facing strings in `t('harmonic:…')`,
and update [`STATUS.md`](STATUS.md). Deviations are written back into this file.

---

## Phase 0 — Foundations (→ M0)

### H0.1 Scaffold

- **Goal:** the empty skeleton every other WP plugs into.
- **Files:** `lib/harmonic-game/{CLAUDE.md,index.ts,LICENSE-CONTENT.md}`; `vitest.tf2.config.ts`
  (add `'lib/harmonic-game/**/*.test.ts'`); `locales/en/harmonic.json` + `NAMESPACES` in
  `lib/i18n/config.ts`; `app/routes/harmonic.tsx` (full-screen, `noindex` per D8,
  `GameErrorBoundary`); `components/harmonic-game/HarmonicPlayPage.tsx` (placeholder
  title screen through `AppShell`, "In development" text, back link).
- **Done when:** `/harmonic` renders the placeholder in both themes; `pnpm test:tf2
lib/harmonic-game` runs (one trivial test); route tree regenerated by the build, not by hand.
- **Deps:** none.

### H0.2 Level compiler

- **Goal:** `compileLevel(LevelSource)` → in-memory `BspFile` + manifest, per
  `architecture.md` §3.
- **Files:** `lib/harmonic-game/compiler/{types.ts,shapes.ts,brush.ts,kd.ts,bsp-build.ts,
materials.ts,index.ts}` + tests.
- **Interfaces:** `compileLevel(src: LevelSource): CompiledLevel` with
  `{ bsp: BspFile; manifest: MapManifest; materials: Map<string, MaterialInfo>; stats: { brushes, faces, leaves, ms } }`.
- **Done when:** tests prove — a 512×512×256 hollow room: `MapCollision` traceLine hits the
  wall at the expected fraction; traceHull with the player hull stops 16u from the wall;
  `pointContents` is SOLID inside a wall and 0 in the room; a `func_door` entity's brush is
  `models[1]` and `model "*1"`; `water` contents reported; faces count = visible sides;
  compiling twice is byte-identical; a 2,000-brush synthetic level compiles in < 250 ms in Node.
  And `SpWorld.create({ game: 'hl2', bsp, assets: createEmptyAssets('hl2') })` spawns the
  player at `info_player_start` and `Driver` can walk it across the floor without falling
  through.
- **Deps:** H0.1.

### H0.3 Procedural assets

- **Goal:** textures, materials and a `SpAssets` implementation with no files.
- **Files:** `lib/harmonic-game/assets/{rng.ts,textures.ts,palette.ts,materials.ts,
harmonic-assets.ts,texture-cache.ts}` + tests.
- **Interfaces:** `MATERIALS: Record<string, MaterialRecipe>` (at least: `concrete`,
  `steel_plate`, `steel_rust`, `paint_white_1971`, `paint_white_2030`, `ice`, `snow`,
  `grating`, `wood_deck`, `glass`, `hazard_stripe`, `nodraw`, `sky`), `buildTexture(recipe,
size): ImageData` (pure, testable in Node), `createProceduralTextureCache(manifest)`
  (browser: canvas → blob URL), `createHarmonicAssets(): SpAssets`.
- **Done when:** each recipe produces deterministic pixels (hash test); the manifest the
  compiler emits names every texture; `createHarmonicAssets().material('ice').surfaceProp`
  is set; no DOM use in the pure parts.
- **Deps:** H0.1 (can run in parallel with H0.2 — agree on `materials.ts` names via this file).

### H0.4 Dev level and client

- **Goal:** milestone M0 — walk around a compiled level at `/harmonic`.
- **Files:** `lib/harmonic-game/levels/{dev_box.ts,index.ts}`; `lib/harmonic-game/client/

- **Interfaces:** `createHarmonicClient(opts: SpClientOptions-like)`; `HARMONIC_LEVELS:
{ id, titleKey, source: () => LevelSource }[]`.
- **Done when:** in a real browser (`pnpm dev`, play-smoke screenshot attached to the PR) the

- **Deps:** H0.2, H0.3.

## Phase 1 — Player and combat (→ M1)

### H1.1 Combat core

- Hitscan + melee + damage routing, `HarmonicCombat` service, player death → reload last
  checkpoint (SP checkpoint system, `lib/sp-game/level/checkpoint.ts`). Optional additive
  `SpWorld` tick hook if needed (architecture §5). **Done when:** a test shoots a target
  entity through `Driver` input and it takes the expected damage; HL2/Portal tests unchanged.
- **As built:** `SpWorld.hooks` (`afterPlayerCmd`, `afterTick`) + `SpContent.attachWorld`; `sim/index.ts`
  `attachHarmonicSim(world)` installs `HarmonicCombat` (`world`-attached; `sim/combat.ts`) and the debug pulse
  (`firePrimary`, the one function H1.3 replaces). Death/checkpoint reload is the engine's (`SpPlayer` →
  `SpWorld.reloadAfterDeath`), unchanged. Test level `dev_combat`.
- **Deps:** H0.4.

### H1.2 Cold and shelters

- Exposure meter, `trigger_harmonic_exposure`, heaters (`harmonic_heater` point entity),
  HUD-facing state. **Done when:** tests drain outdoors / refill indoors at the specified
  rates (constants in `sim/constants.ts`), health ticks at zero.
- **Deps:** H1.1.
- **As built (H1.2):** `sim/cold.ts`. `sim.cold: ColdService` (`value`, `max`, `mode`, `warmth`,
  `enabled`, `sheltered`, `frost`, `hint`, `hudState()`, `reset()`, `tick(dt)`), driven from
  `afterTick`. `activeHarmonicSim()` (sim/index.ts) gives the HUD the running sim;
  `readHudState(snap, sim?)` fills `cold` (`{value,max,sheltered,frost}`) and `hint`. Entities:
  `trigger_harmonic_exposure` (keys `mode` outdoor|shelter|wind, `area`, `hint`, `hintkey`; input
  `SetMode`; shelter beats wind beats outdoor where volumes overlap) and `harmonic_heater` (a
  `PropDynamic`; keys `radius`, `StartDisabled`; inputs `Enable`/`Disable`/`Toggle`; output
  `OnPlayerWarm`; warmth falls off linearly, added to the base rate, no wall occlusion).
  Level default: `LevelSource.exposure` (`'outdoor'|'shelter'`, absent = shelter = no meter) and
  `exposureArea` (worldspawn `harmonic_exposure` / `harmonic_area`). Area changes publish
  `{type:'area'}` on `harmonicSounds`. Reset happens when the player is alive again after a death
  (not checkpointed). Constants: `COLD_*` in `sim/constants.ts`. Test level `dev_cold`. The
  browser harness (`scripts/harmonic/models-harness`) now overlays `HarmonicHud`.

### H1.3 Weapons

- `harmonic_weapon_prybar` (melee, pries `func_breakable` panels), `harmonic_weapon_pulse`
  (pistol, 12 rounds), `harmonic_weapon_coil` (rifle, 30 rounds, ADS zoom), ammo pickups,
  inventory + `weaponSelect`. Numbers in a table `sim/weapon-table.ts`. **Done when:** tests
  for fire rate, ammo, reload, switching, pickup; view models drawn (procedural, H2.4 can stub).
- **As built:** `sim/weapon-table.ts` (every number; `WEAPONS[id]`, `RESERVE_MAX`, `AMMO_PICKUP_AMOUNT`),
  `sim/weapons.ts` (`HarmonicWeapons`, reached as `harmonicSim(world).weapons`; replaces the debug `firePrimary`,
  whose `DEBUG_PULSE_*` constants are gone), `sim/pickups.ts` (`harmonic_weapon_{prybar,pulse,coil}`,
  `harmonic_ammo_{pulse,coil}`; key `amount`, output `OnPickup`), level `dev_weapons`.
  API for later WPs: `weapons.state` (`owned/clip/reserve/active`), `give(id, reserve?)`, `pickupWeapon(id)`,
  `addAmmo(type, n?)`, `select(slot)`, `startReload()`, `hud()` (the `HarmonicHudState.weapon` slice; melee has none),
  `on(fn)` events `draw|fire{hit}|empty|reload|reloaded|pickup|ads`, `ads`/`zoomFov`, `spreadOffset(shot, deg)`.
  Controls: number keys → `cmd.weaponSelect` (slot), wheel → `SpContent.weaponContext`, R = `IN_RELOAD`, attack2 = ADS
  (coil only; the sim emits the engine's existing `zoom` event). Pistol is semi-auto, coil full-auto; an empty click
  auto-reloads when reserve remains. Prybar does `PRYBAR_PANEL_DAMAGE` to a `func_breakable` (breaks in two swings).
  Sounds go through `harmonicSounds` (`*.fire/reload/empty`, `melee.swing/hit`, `impact.<surface>`, `pickup`).
  **Checkpoint rule:** the inventory is part of the checkpoint (captured when `world.checkpoint` changes); dying
  restores it as it was at the level start / last autosave, matching the pickups the engine restores, so nothing is
  farmed by dying. Start with nothing (levels grant weapons via pickups). Engine seams (additive, `docs/tf2-game.md`):
  `SpContent.weaponContext?` and `SpContent.viewModel?` (`SpViewModelFrame`). `readHudState(snap, sim?)` fills `weapon`.
  Gaps: ammo pickups reuse the weapon's world model (no ammo-box model yet); reload clips are fixed at 1.5 s so the
  pistol (1.2 s) returns to idle early; `scripts/harmonic/weapons-smoke.ts` is the browser check.
- **Deps:** H1.1.

### H1.4 HUD, pause, saves

- HUD (health, cold, ammo, Tuner charge, subtitles slot, hint line), pause menu, options

  **Done when:** HUD reflects sim state in the browser; save/continue round-trips; both themes.
- **Deps:** H0.4.

## Phase 3 — Narrative and audio (→ M1)

### H3.1 Dialogue + subtitles

- `harmonic_dialogue` entity, script runner, radio (Odile) channel, speaker colours,
  pause-aware. **Done when:** a level's I/O starts a script; subtitles show in order; keys
  extracted by `pnpm i18n:extract`.
- **Deps:** H1.4.
- **As built (H3.1).** `lib/harmonic-game/narrative/`: `DialogueScript { id, lines, then?, once? }`,
  `DialogueLine { speaker, key, defaultValue, durationMs?, channel?: 'radio'|'voice' }`
  (`types.ts`); builders `say()` / `radio()` (`speakers.ts`); registry `findScript(id)` /
  `ALL_SCRIPTS` (`scripts/index.ts`; add `scripts/ch<N>.ts` there); `DialogueRunner(clock)` with
  `start(script, { source?, interrupt? })`, `cancel(idOrSource?)`, `skip()`, `tick()`, `current()`,
  `hasPlayed(id)`, `reset()`, `on(listener)` (`runner.ts`); per-world `attachNarrative(world)` /
  `getNarrative(world)` → `NarrativeService { runner, showHint(owner,key,default), hideHint(owner),
readHud(hudNow), reset() }`. Entities (`import '.../narrative'` registers them):
  `harmonic_dialogue` (key `script`, `interrupt`; inputs `Start`, `Cancel`; outputs `OnLine<N>`,
  `OnFinished`, the script's `then` names, `OnCancelled`) and `harmonic_hint` (keys `hintkey`,
  `hinttext`, `duration`; inputs `ShowHint`, `HideHint`). The service is attached lazily by those
  entities and ticked from their think, so `sim/index.ts` is untouched; the HUD slice is merged by
  `applyNarrativeHud` in `harmonicContent().hud`. Time is `world.curtime` (stops while paused);
  subtitle `until` = HUD now + sim time left. `+use` skips a line after 0.4 s (no options key yet).
  Radio lines emit `radio.click` + `radio.static` on the audio bus. HUD subtitles gained optional
  `speakerId` / `channel`; speaker colours are `--harmonic-speaker-<id>` tokens. Keys `dev.*`,
  `speaker_*`, `hud_radio` are in `locales/en/harmonic.json` by hand; `narrative.test.ts` checks every
  script key against it. Browser check: `scripts/harmonic/dialogue-smoke.ts` (harness `?hud=1`).

### H3.2 Chapter flags and endings framework

- Flags in save, ending selection entity, epilogue routing. **Done when:** tests.
- **Deps:** H3.1.
- **As built (H3.2).** `narrative/flags.ts`: `HARMONIC_FLAGS` (typed rows: `sanaHelped`, `vossSpared`,
  `ending`, `chapterReached`, dev flags; add a flag = add a row), `getFlags(world): FlagService`
  (`get(name)`, `set(name, value): boolean` — type/enum checked, `all()`, `persist(level)`,
  `restoreLevelStart()` for the death reload), `parseFlagValue`, `noteChapterReached(level)`,
  `furthestChapter(flags)`, `setDefaultFlagStorage(s)` (tests). The service starts from the save's flags
  and writes them back (merged over unknown keys) on chapter end and on an ending; `harmonic-client.ts`
  calls `noteChapterReached` + `flow.levelLoaded` from `loadLevel`. `narrative/chapters.ts`:
  `HARMONIC_CHAPTERS` (`{ id, number, titleKey, titleDefault }`, h1..h7), `HARMONIC_DEV_CHAPTERS`
  (`dev_flow_a/b`), `chapterById`, `nextChapter(id)`, `EPILOGUE_LEVELS`, `flowCommand` / `parseFlowCommand`.
  Entities (`narrative/flow-entities.ts`): `harmonic_flag` (`Set [name] <value>`, `Test [name]` →
  `OnTrue`/`OnFalse`/`OnValue<value>`), `harmonic_chapter_end` (`End` → saves with the NEXT chapter as the
  slot level, `OnEnd`, then a `clientcommand`), `harmonic_ending` (`Choose anchor|release|silence` → sets
  `ending`, saves, `OnChosen`, goes to `h7_epilogue_<ending>`). A target level with no source in
  `HARMONIC_LEVELS` is "not available": the client shows "End of the current build". `narrative/endings.ts`:
  `endingLines(ending, flags)` → `[base, sana variant, voss variant]` (`{ key, defaultValue }`, keys
  `ch7.ending.<ending>.<slot>`, already in `locales/en/harmonic.json` — H4.7 rewrites the defaults under NEW
  keys), `ALL_ENDING_LINES`, `epilogueLevel`. Client (`client/flow.ts`, `ChapterFlow`): fade to black
  (`CURTAIN_MS`), load, chapter title card (`hud.chapter`, `hud.curtain` in `HarmonicHudState`). Engine
  seams: `SpContent.onClientCommand` + `GameCanvas endScreen` (docs/tf2-game.md). Title screen lists
  "Chapters" up to `flags.chapterReached`. Test level `dev_flow.ts`; tests `narrative/flow.test.ts`;
  browser check `scripts/harmonic/flow-smoke.ts` (`harness` / `site`). Chapter WPs: put the finish trigger →
  `harmonic_chapter_end End`; ch2 sets `sanaHelped` and ch6 `vossSpared` with `harmonic_flag Set <name> 1`;
  H4.7 wires the console to `harmonic_ending Choose <ending>` and plays `endingLines`.

### H3.3 Audio

- **Deps:** H0.4.

Level transitions: **decided in H3.2 — the `harmonic_chapter_end` entity**, not the engine's
`trigger_changelevel` (levels are compiled from TypeScript: no landmarks, nothing to carry over).
A chapter's finish trigger fires `harmonic_chapter_end End`; add the chapter to `HARMONIC_LEVELS`
(its id is already in `HARMONIC_CHAPTERS`) and the transition, title card and "Chapters" entry work.

- **As built (H4.1):** `levels/h1_whiteout.ts` (`h1WhiteoutSource()`, exported `H1` waypoints/boxes), scripts
  `narrative/scripts/ch1.ts` (`CH1_SCRIPTS`, ids `ch1.<scene>`), keys by hand in `locales/en/harmonic.json`.
  Pattern for later chapters: a distant "ghost" is a `func_brush` (`solidity 1`, `StartDisabled 1`) that a
  `logic_relay` enables/disables on a timed list of delayed outputs, started from a dialogue `OnLine<N>`; the
  level ceiling is `snow` far above the fog end (the `sky` material is not fogged and shows as a hard slab);
  sounds from level I/O use `ambient_generic` (`message` = bank name, spawnflags 49) + `PlaySound`. The chapter
  ends by `fence_dialogue OnFinished -> chapter_end,End` (`harmonic_chapter_end`, class owned by H3.2).
  Tests must `import '../narrative'` or dialogue entities are never registered. ~850 brushes, no enemies;
  cold budget walks the path ending >15/100 with both shelters used.
