# Balatro multiplayer — parity tracker

> Not published: `docs/conf.py` excludes this file (`/balatro` is unlisted).
> Generated by WS0 from the project plan's feature checklist (§2); maintained by
> WS14 from here on. Companion to [`balatro-mp.md`](balatro-mp.md).

Every feature of the reference multiplayer mod is listed here, with the workstreams
that own it. Nothing is dropped: exclusions are in the last section, with reasons.

**How to update.** Check a box only when a test proves the item, and name that test
next to it, for example:

```text
- [x] LOB-05 Guest Ready/Unready … — WS5, WS10 — `testing/balatro-e2e/match/lobby.test.ts` (E2E-01)
```

Use an in-engine L2 spec (`lib/balatro/lua/mp_test/specs/*_spec.lua`), an L1 Lua spec,
a `pnpm test:balatro` test or an e2e scenario (E2E-xx). Parity sign-off (wave 4) is
every box checked.

Open items at generation: **185** checklist lines.

**WS14b sign-off (2026-10-30):** every line is checked with the tests that prove it
(unit and integration tests under `pnpm test:balatro`, Lua L1 specs, in-engine L2 specs under
`lib/balatro/lua/mp_test/specs/`, and the match e2e scenarios under
`testing/balatro-e2e/match/`, E2E-xx). **NET-09** (`visibilitychange` → away), the last open
line, was closed afterwards with a frozen-contract addition: the member→host wire kind
`visibility` (see the item). A scenario reference (E2E-xx) means the scenario passed on the
local stack (hub + `vite dev` + Postgres, real browsers and bot peers).
