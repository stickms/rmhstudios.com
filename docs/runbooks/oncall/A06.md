# A06 — Database connections / pool saturated

**Sev2.** Two instances:

- **`A06:connections`**: Postgres has more than 85% of `max_connections` in use for 3 minutes.
- **`A06:pool`**: 5 or more web requests are queued waiting for a pooled connection.

1. Who holds the connections?
   `sudo -u postgres psql -c "select application_name, state, count(*) from pg_stat_activity group by 1,2 order by 3 desc"`
2. Long-running or idle-in-transaction sessions:
   `... where state <> 'idle' and now() - query_start > interval '1 minute'`. Cancel a runaway with `select pg_cancel_backend(<pid>)`.
3. A deploy just ran two web colours at once? That's expected for a few minutes; it should clear after the swap.
4. Persisting: restart the service holding the most connections (web, jobs, a hub).
