# D05 — Release auto-rolled back on alarms

**Sev2.** Within 15 minutes of a deploy, the page/API 5xx or latency alarms
(A08 / A09) fired on the new release's own traffic, twice in a row, so the
post-deploy guard redeployed the previous release.

1. The alert names the release and the alarm. Confirm the redeploy finished in
   the deploys channel; the guard's log is `/home/rmhstudios/post-deploy-guard.log`.
2. Production is back on the previous release; the bad commit is still on `main`.
   Fix forward (or revert) — the next deploy re-runs the guard.
3. Migrations from the bad release stay applied (they are forward-only).
4. A false alarm? Tune the threshold on `/admin/alarms` → Alarm rules.
