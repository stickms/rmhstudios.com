# A04 — Nightly database backup missed

**Sev2** (it is the only copy of user data off the box). No successful
`pg-backup` check-in for 26 hours.

1. `systemctl list-timers | grep rmh-db-backup`: is the timer installed and scheduled?
2. `journalctl -u rmh-db-backup.service -n 100`: what did the last run say?
   (A [BACKUP](BACKUP.md) Sev3 usually fired with the exit code.)
3. Fix the cause, then run it now: `sudo systemctl start rmh-db-backup.service`.
   A successful run clears this alarm.
4. Check the newest object under `daily/` in the backup bucket has today's date.

Common causes: the unit's `WorkingDirectory` not matching the repo path,
expired backup bucket credentials, a full `/var/tmp`.
