# B07 — Discord bot disconnected

**Sev3.**
The
Discord
bot's
gateway
has
not
been
READY
for
5
minutes
after
having
connected;
`/chat`
and
Alex
are
offline.

The
bot
runs
in
the
Node
`jobs`
worker
(`server/discord-bot/`).
Every
minute
it
runs
the
pg-boss
job
`discord-bot.gateway-heartbeat`,
which
completes
only
while
the
gateway
is
READY
and
fails
otherwise.
The
status
service
raises
B07
when
the
newest
completed
heartbeat
is
over
5
minutes
old
while
that
queue
is
scheduled;
with
no
bot
token
the
bot
unschedules
it
and
B07
stays
quiet.

1. Discord
   outage?
   https://discordstatus.com
2. Is
   `jobs`
   up?
   If
   [A16](A16.md)
   is
   firing
   too,
   fix
   that
   first.
3. `docker logs <jobs container> --since 30m | grep discord_bot`:
   `gateway_closed_fatal`
   (token
   revoked
   or
   intents
   not
   allowed),
   `gateway_open_retry`
   /
   `gateway_open_failed`
   (cannot
   reach
   the
   gateway),
   `discord_bot.disabled`
   (no
   token
   in
   `.env.production`).
4. `SELECT state, count(*), max(completed_on) FROM pgboss.job WHERE name = 'discord-bot.gateway-heartbeat' GROUP BY state;`
   —
   recent
   `failed`
   rows
   and
   an
   old
   `completed`
   =
   the
   gateway
   is
   down;
   no
   recent
   rows
   at
   all
   =
   the
   queue
   is
   not
   being
   consumed
   (jobs
   down
   or
   the
   bot
   failed
   to
   register).
5. Restart
   to
   reconnect:
   `docker compose -p rmhstudios-prod --env-file .env.production up -d --force-recreate jobs`
   (from
   the
   repo
   checkout).
   There
   must
   be
   no
   `rmhstudios-prod-supervisor`
   container
   left
   (`docker ps -a | grep supervisor`);
   if
   there
   is,
   `docker rm -f`
   it
   —
   it
   would
   run
   a
   second
   bot
   on
   the
   same
   token.
