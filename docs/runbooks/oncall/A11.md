# A11 — Background worker down / crash-looping

**Sev2.** The Go supervisor runs six workers (discord-bot, recap, doctrine-worker, vibe-worker, bot-worker, streak-saver). Instances:

- **`A11:<worker>`**: that worker isn't running (`rmh_worker_up` 0 for 2 minutes): it returned early or is waiting out a panic backoff.
- **`A11:<worker>-panics`**: it panicked 3+ times in 15 minutes. The supervisor recovers and restarts it each time, so the other five keep running.

1. `docker logs <supervisor container> --since 30m | grep '"worker":"<worker>"'`. Look for `worker panic` (it logs the stack) or `worker exited before shutdown`.
2. Bad release? Roll back the deploy. The supervisor is not auto-rolled back.
3. Restart: `docker compose -p rmhstudios-prod --env-file .env.production restart supervisor` (restarts all six).
