# A02 — Readiness failing (`/api/ready`)

**Sev2.** `/api/ready` checks the database and Redis behind the web tier.
It returned non-200 (or not `"status":"ok"`) twice in a row.

1. The alert's detail has the response body, which names the failing dependency.
2. Postgres: `sudo systemctl status postgresql`; `df -h` (a full disk stops
   Postgres); `dmesg -T | grep -i oom` (the OOM killer).
3. Connections exhausted? `sudo -u postgres psql -c "select application_name, count(*) from pg_stat_activity group by 1 order by 2 desc"`.
4. Redis: `docker ps | grep redis`; if it is restart-looping, `docker logs <redis container> --tail 50`.
5. Started right after a deploy? Roll back: [web hotswap rollback](../web-hotswap-rollback.md).
