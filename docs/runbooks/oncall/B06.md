# B06 — Background job stale

**Sev3.** A cadence job hasn't succeeded within its limit. Two sources:

- **Go supervisor jobs** (read from the supervisor's `/metrics`): none have a cadence limit right now (the rule in `internal/status/workers.go` `staleLimits` is empty).
- **Node `jobs` worker** (read from pg-boss's job table by the status service, latest `completed` run): `streak_sweep` (3 h; pg-boss queue `streak.reminder-sweep`, hourly at :23), `recap` (20 min; queue `lights-out.recap`, every 5 min) and `sahur_activation` (10 min; queue `doctrine.sahur-activation`, every minute).

1. Node jobs: `docker logs <jobs container> --since 1h | grep -i '<recap|doctrine>'`, then check the queue: `SELECT state, count(*), max(completed_on) FROM pgboss.job WHERE name = '<queue>' GROUP BY state;`. A run in `failed` means the job threw (for recap: the due-channels query; per-guild Discord failures are logged, not failed). No runs at all means the jobs container is down or the queue failed to register (`jobs.register_failed`).
2. `streak_sweep`: `docker logs <jobs container> --since 3h | grep -i streak-saver` (also look for `jobs.register_failed` with `queue":"streak.reminder-sweep"` at boot). Check the queue: `SELECT state, count(*), max(completed_on) FROM pgboss.job WHERE name = 'streak.reminder-sweep' GROUP BY state;` A run in `failed` means the at-risk query threw (database); no runs at all means the jobs container is down or `STREAK_REMINDER_ENABLED=false` (then the alarm stays quiet once old runs are pruned).
3. If the worker is down instead, the jobs container heartbeat fires too.
