## Intent and why

The
main
site
is
sluggish,
including
on
strong
hardware.
The
cause
is
the
material
itself,
not
a
bug.
A
normal
desktop
page
runs
up
to
24
WebGL
rim
canvases,
8
WebGL
haze
canvases,
24
animated
CSS
carriers,
a
60
Hz
ambient
clock
that
never
goes
idle
while
the
tab
is
visible,
a
soft-body
physics
service,
electric
arcs,
and
a
DOM-to-bitmap
snapshot
loop
(`lib/liquid/glass/scene.ts`,
100–300
ms
of
time-sliced
main-thread
work
at
most
every
1.5
s).
The
only
escape
hatch
is
`html.perf-lite`,
which
strips
most
of
the
material
and
is
only
set
when
a
software
renderer
is
detected.

Move
the
material
to
**static,
baked
CSS
plus
event-woken
effects**,
so
a
page
at
rest
does
no
work
and
the
look
survives
for
everyone,
not
just
on
a
fast
GPU.
Keep
what
makes
RMH
Studios
feel
like
itself:
the
hazy
gel,
the
RGB-led
molded
rim,
plasma
that
wakes
under
the
hand,
a
body
that
is
soft
to
press,
and
the
arc
when
you
click.

## Design

**1.
Material
is
static
CSS.**
The
CSS
tier
in
`app/jelly-material.css`
/
`app/liquid-glass.css`
(gel
gradient,
haze
floor +
`public/jelly/haze-tile.webp`,
static
rim)
becomes
the
primary
material.
The
rim
gets
the
RGB-led
molded
look
in
CSS:
shoulder
lit
on
the
light
side,
soft
shadow
on
the
far
side,
red
toward
the
top-left
light
and
blue
away,
via
stacked
inset
shadows
/
gradients,
or
a
baked
sprite
generated
by
a
script
like
`scripts/generate-jelly-haze-tile.mjs`
if
the
stack
cannot
reach
the
look.
_My
call:_
try
the
zero-asset
stack
first;
add
sprites
only
if
it
falls
short.

**2.
Motion
is
woken,
not
ambient.**
Haze
drifts
only
under
`:hover`
/
`:focus-within`
(`animation-play-state`),
and
where
`animation-timeline: view()`
is
supported
(`supportsViewTimeline`
already
exists)
it
can
be
tied
to
scroll
instead
of
time.
`Still`
=
no
haze
motion;
`Calm`
=
slower
and
fainter.
Nothing
runs
on
an
idle
page.

**3.
Soft
body
is
CSS.**
Hover
plumps
(scale
≤
1.03),
press
squashes,
release
springs
back,
using
`transition`
with
`linear(...)`
spring
curves
authored
once
as
tokens
(`--spring-*`)
and
derived
from
the
existing
physics
constants.
A
fine-pointer-only
delegated
`pointermove`
writes
`--px/--py`
on
the
single
hovered
host,
which
positions
the
plasma
wake
and
the
dent's
light
dot
(a
radial
gradient).
No
per-component
listeners.
`MOTION_BOUNDS`
unchanged.

**4.
Arcs
are
events.**
On
click,
a
lazily
created
canvas
draws
one
burst
(bolts
per
tier
budget),
then
is
removed
after
idle.
`dischargeAt`
/
`strike`
stay
exported
so
`app/routes/jelly.tsx`
and
existing
callers
keep
working.
The
3-onsets/s
flash
ledger
stays
(WCAG
2.3.1).

**5.
Removal.**
Once
nothing
installs
them:
the
engine's
slab,
haze,
cursor-light,
dent
and
lattice
code,
the
rim/haze
worker
path,
registry,
lattice/envelope/room,
ambient
arcs
and
field,
ambient
clock,
the
matching
tests
and
the
unwired
`testing/e2e`
scripts
for
them.
**Kept
for
the
globe:**
the
snapshot
path
(`scene.ts`,
`scene-store.ts`,
the
engine's
publishing
code
in
a
reduced
globe-feed
mode),
the
governor's
DPR
cap,
and
the
GLSL/colour/policy
modules
the
globe
imports
(listed
under
Non-goals).

## Constraints and risks

- **Merging
  to
  `main`
  deploys
  to
  production**
  (push
  to
  `main`
  →
  GitHub
  Actions
  →
  image
  →
  VPS
  blue/green).
  Every
  merge
  is
  live.
  Hence
  small,
  revertible
  PRs,
  and
  none
  merges
  on
  red
  CI.
- **Hydration:**
  carriers
  are
  DOM
  nodes
  injected
  after
  load
  (to
  avoid
  hydration
  error
  #418).
  The
  CSS
  version
  must
  not
  inject
  nodes;
  it
  uses
  the
  host's
  own
  background
  layers
  or
  pseudo-elements.
  Role
  classes
  already
  use
  some
  pseudo-elements,
  so
  collisions
  are
  the
  biggest
  technical
  risk
  (builder
  to
  survey).
- **Rule
  amendments.**
  `CLAUDE.md`
  forbids
  `transition: transform`
  on
  a
  body,
  keyframe
  wobble
  and
  "faking
  a
  law".

  springs
  reverse
  that
  deliberately;

  is
  rewritten
  to
  "one
  spring
  source
  (tokens),
  no
  per-component
  curves".
  CSS
  transitions
  do
  not
  carry
  velocity
  across
  an
  interrupted
  state
  change
  like
  the
  current
  springs
  do;
  accepted.
- **Verification
  environment.**
  This
  sandbox
  has
  Node
  22
  (repo

  and

  until
  that
  is
  fixed.
  _My
  call:_
  step
  0
  is
  to
  get
  Node
  24 +
  `pnpm install`
  working;

## Decisions (owner, 2026-11-07) — design approved

1. **The
   engine
   stays,
   for
   the
   globe
   only.**
   The
   globe
   keeps
   refracting
   the
   page
   behind
   it,
   so
   the
   glass
   engine's
   snapshot
   capture
   (`scene.ts`,
   `scene-store.ts`)
   and
   the
   engine
   module
   that
   publishes
   it
   remain.
   What
   goes
   is
   everything
   the
   engine
   does
   for
   site
   surfaces:
   rim
   slabs,
   haze
   canvases,
   the
   ambient
   clock,
   lattice
   stepping,
   cursor
   light
   and
   dent
   drawing.
   The
   engine
   is
   reduced
   to
   a
   **globe-feed
   mode**:
   slab
   budget
   0,
   haze
   0,
   clock
   0,
   snapshot
   on.
   _My
   call
   within
   that:_
   the
   snapshot's
   triggers
   shrink
   to
   load,
   route
   change,
   theme
   change
   and
   resize
   (no
   scroll-rest
   or
   content-mutation
   recapture),
   keeping
   the
   1.5
   s
   minimum
   interval,
   and
   it
   only
   runs
   while
   the
   globe
   is
   mounted.
   PR
   5
   deletes
   the
   engine's
   slab/haze/lattice
   code,
   not
   the
   snapshot
   path,
   and
   moves
   the
   surviving
   pieces
   behind
   a
   name
