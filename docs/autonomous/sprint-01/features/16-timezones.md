# 16 · Time zone converter (`/tools/timezones`)

Dates

time.
Branch:
`autonomous/s01-timezones`.
Status:
shipped

## User story

As
a
member
organising
a
game
night
or
a
call
across
countries,
I
want
to
see
one
moment
in
several
time
zones
with
day
changes
and
working
hours
so
that
I
can
pick
a
time
that
suits
everyone.

## Requirements elicitation

Who:
members
of
the
site
(and
signed-out
visitors,
since
every
tool
is
public)
who
would
otherwise
paste
the
same
data
into
an
unknown
third-party
website.
Why
here:
the
site
already
hosts
the
developer
API,
RMHCode,
RMHStudy,
the
vibes
platform,
communities
and
group
chats;
these
are
the
jobs
those
users
do
next
to
them.
Constraints
from
the
repository:
Steel
design
language,
`t()`
for
every
string,
a
public
route
with
its
own
meta
and
an
OG
card,
no
server
round
trip
for
user
data,

new

## Specification

### Functional requirements

- **F1.**
  Choose
  a
  source
  zone,
  date
  and
  time
  (default:
  the
  viewer's
  zone
  and
  now).
- **F2.**
  Show
  the
  moment
  in
  each
  listed
  zone
  with
  local
  time,
  date,
  day
  change,
  UTC
  offset
  and
  whether
  it
  is
  working
  hours,
  early
  or
  late,
  or
  night.
- **F3.**
  Add
  zones
  from
  the
  browser's
  full
  IANA
  list
  and
  remove
  them;
  the
  list
  is
  saved
  per
  device
  in
  local
  storage
  through
  lib/core/persist.
- **F4.**
  Use
  the
  browser's
  own
  Intl
  data;
  ship
  no
  time-zone
  database.
- **F5.**
  Place
  a
  time
  skipped
  by
  a
  spring-forward
  change
  after
  the
  gap
  and
  say
  so;
  take
  the
  first
  of
  two
  repeated
  autumn
  times.

### Non-functional requirements

- **Privacy
  and
  security.**
  Everything
  runs
  in
  the
  browser;
  no
  input
  is
  sent
  to
  the
  server,
  logged
  or
  stored,
  except
  where
  a
  requirement
  above
  names
  local
  storage.
  Randomness,
  where
  used,
  is
  `crypto.getRandomValues`
  through
  `lib/toolbox/random.ts`
  (rejection-sampled),
  never
  `Math.random()`.
- **Performance.**
  Pure
  functions
  with
  no
  dependency;
  work
  proportional
  to
  the
  input,
  bounded
  by
  explicit
  limits;
  expensive
  recomputation
  deferred
  with
  `useDeferredValue`
  where
  input
  is
  long.
  Nothing
  animates
  or
  polls
  at
  rest
  (Steel
  R5);
  no
  worker,
  observer
  or
  animation
  frame.
- **Accessibility.**
  Every
  control
  is
  labelled
  (`Label`/`aria-label`),
  results
  that
  change
  are
  in
  an
  `aria-live`
  region,
  errors
  use
  `role="alert"`,
  state
  is
  never
  conveyed
  by
  colour
  alone,
  focus
  ring
  is
  the
  global
  K10
  outline,
  and
  tab
  switchers
  use
  the
  shared
  `Tabs`
  (roving
  keyboard).
- **Design
  system
  (Steel).**
  `ToolFrame`
  (PageLayout),
  rows
  on
  1px
  rules
  (R3),
  `--site-*`
  token
  utilities
  only,
  `t-*`
  type
  classes,
  at
  most
  one
  ink
  primary
  button
  per
  view
  (R4),
  no
  gradient,
  blur,
  shadow
  or
  translucency
  (R1).
- **i18n.**
  All
  strings
  through
  `t()`
  in
  the
  `toolbox`
  namespace
  with
  literal
  defaults;
  numbers
  and
  dates
  through
  `Intl`
  in
  the
  active
  locale;
  layouts
  survive
  RTL
  (`ar`).
- **SSR.**
  Output
  that
  depends
  on
  the
  clock,
  the
  viewer's
  time
  zone
  or
  randomness
  renders
  only
  after
  hydration,
  so
  server
  and
  client
  agree.
- **SEO.**
  `definePage`
  gives
  the
  route
  its
  own
  title,
  description
  and
  canonical;
  it
  unfurls
  with
  the
  `/tools`
  section
  card;
  it
  is
  listed
  in
  the
  sitemap
  from
  the
  catalog.
